# 007 편집형 홈과 축구 통계 이야기

## 목적과 경계
축구 자료에 대한 독창적인 질문·관찰·해석·한계를 사이트 본체로 제공한다. 승무패 도구는 공개된 부가기능으로 유지한다. 검색엔진이나 심사자에게 다른 내용을 보여주지 않는다. 승인 보장, 공식 글자 수·발행 횟수 기준 주장, 광고 로더 활성화는 하지 않는다.

이번 분담의 쓰기 범위는 `src/lib/stories.ts`, `tests/stories.test.ts`, 이 문서뿐이다. 공용 메뉴·홈·라우터·CSS·리그 소개·배포는 부모 작업이다. DB 변경은 없다.

## 화면 순서
- 홈: 소개 → 대표 이야기 → 방법론 이야기 → 최신 데이터 화면 링크 → 출처·편집 원칙 → 승무패 부가기능.
- 아카이브 `/stories`: 소개 → 완성 기사 3개. 초기에는 검색창·빈 필터·준비 중 카드가 필요 없다.
- 기사: 단일 H1·작성 주체·AI 보조·발행일·자료 기준/범위 → 질문 → 관찰/반례 → 해석/검증 조건 → 한계 → 원자료 → 정정 원칙 → 관련 기사.
- 대표 카피: ‘축구 숫자, 어디까지 말할 수 있을까’. 부가기능은 회차별 확률 조회·설정 시뮬레이션·조합 계산임을 밝히고 구매 권유·수익 보장과 구분한다.

## 구현 인터페이스
- `STORIES: readonly Story[]`: 완성된 기사 3개. `body`는 저장소에 작성한 신뢰된 HTML이며 사용자 입력을 넣는 인터페이스가 아니다. 제목·요약·메타 필드는 출력 시 escape한다.
- `storyCards()`: `.site-grid` 내부에 넣을 `article.site-panel` 3개만 반환한다. wrapper는 호출자가 제공한다.
- `renderStoriesIndex()`: `/stories`, 이벤트 `stories_view`, 완성 HTML.
- `renderStory(slug)`: 알려진 슬러그에만 완성 HTML. 나머지는 null로 부모 라우터가 404 처리한다. 이벤트 `story_view`.
- `STORY_PATHS`: `/stories`와 기사 경로 3개. snapshot JSON 경로는 사이트맵 목록에 넣지 않는다.
- `LALIGA_SNAPSHOT`: 부모 라우터에서 `/stories/laliga-draw-sample/snapshot.json` JSON 응답으로 제공한다. 객체 직렬화 이외 재집계하지 않는다.
- 부모는 위 이벤트를 `usage.ts` 허용 목록에 추가하고 사이트맵·라우팅·공용 메뉴를 연결한다. 이 모듈은 광고 스크립트를 추가하지 않는다.

## 고정 집계 자료
기준 `2026-11-16T14:26:05.537Z`, 라리가 1,260경기/무승부 329경기. 원 비교 수치는 1,261/330. 의심 행 id=964046, 2026-12-09 Rayo Vallecano–Athletic Club 0:0을 해당 진단 시점에서 제외하고 팀명 별칭 중복 정리를 적용한 값이다. 비율은 329/1260, 표시는 26.1%다.

이것은 전체 경기 원본 데이터가 아닌 **집계 스냅샷**이다. 특정 시즌 전체나 역대 전체가 아니며 기간·수집 완전성·직접 유입원·올바른 날짜·실제 종료 여부는 미확정이다. 원 DB 복구나 예측 입력 정상화를 뜻하지 않는다. 고정된 제외 행은 날짜가 지나도 이 스냅샷에서 다시 포함하지 않는다.

## 기사 논증
1. `laliga-draw-sample`: 표본 무승부 빈도와 다음 경기의 조건부 확률은 다르다. 미래 행 제외는 주 논증을 뒷받침하는 집계 조건이며 QA 회고 자체가 주제가 아니다.
2. `points-and-elo`: 승점 표와 Elo의 목적이 다르며 동률 정렬·비교 팀 집합만으로도 표시 순서가 달라질 수 있다. 순위 차이는 저평가나 반등 증거가 아니다. 허구 경기·팀 사례 없음.
3. `probability-and-accuracy`: 1순위가 같으면 확률 크기가 달라져도 적중률은 같다. 사전 기록·같은 평가 집합·출처 구분이 검증 조건이다. 로그손실과 Brier 정의는 방법 설명이며 실제 성과 우수성을 주장하지 않는다.

모든 기사는 5절 이상. 방법론 기사에는 최신 성과 수치가 없으므로 dataAsOf=null이며 그 의미를 화면에 표시한다. 라이브 원자료 링크를 고정 성과 스냅샷으로 부르지 않는다.

## 날짜·메타데이터·정정
초기 발행 날짜는 2026-11-16. 발행 전 변경 가능하다. 현 코드의 자정 ISO는 날짜를 표현하기 위한 값이며 실제 게시 시각이 확정되면 교체한다. 최초 dateModified는 datePublished와 같다. 이후 정정 때는 해당 기사의 수정 시각 필드를 추가해 JSON-LD와 화면 정정 이력에 함께 반영해야 한다.

Article JSON-LD는 Organization HYEOKS 저자·ISO 발행/수정일·canonical URL·출처를 포함한다. 숫자 기사는 Dataset 참조와 고정 스냅샷 기준 시각도 포함한다. JSON 문자열의 `<`와 줄 구분자를 escape한다. 공용 WebPage JSON-LD와 공존한다. 새 기사는 noindex를 사용하지 않는다.

## 모바일·접근성
360px에서 좌우 16px, 1열 카드. 본문 16px/1.75, 기사 최대 폭 720~780px. 기존 `site.css` 네이비 #101624, 패널 #182131, 밝은 글자, 골드 #edbc68을 계승한다. 메뉴 터치 높이 44px, 필요하면 자연스러운 두 줄 배치. 본문 건너뛰기·키보드 포커스 유지. 표가 필요해지면 표 영역에만 가로 스크롤을 둔다.

## 기존 기능 보존
`/matches`, `/league/*`, `/match/*`, `/ratings`, `/performance`, `/insights/*`, `/guide/*`, `/round/*`, `/app`을 삭제하거나 기사로 덮어쓰지 않는다. `/?round=`, `/?view=`, `/?tab=`의 기존 쿼리 전달 302도 유지한다. 근거: `docs/COLLAB.md:144–150`, `src/routes/sitePage.ts:40–44`.

## 검증
`tests/stories.test.ts`는 고정 분자·분모·비율·제외 행, 유일한 슬러그 3개, 5절 이상, 단일 H1, canonical, Article JSON-LD, 저자·AI·출처·정정 고지, unknown slug=null, 광고 로더 없음, 표본 한계를 검사한다. 전체 CI와 통합 라우팅 검사는 부모 담당이다.
